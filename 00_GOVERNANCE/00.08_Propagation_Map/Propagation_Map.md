# 00.08 · Propagation map — every change reaches every department

*Accepted 2026-10-15 (Owner): "whatever we define — concepts to progression — every edit, insertion,
deletion or new file is done by each responsible agent in the company's folders". The main session plays
each department's role, following that department's `_AGENT.md` (no subagents unless the Owner asks).
Propagation runs **at the end of every work session** and before any ticket closes. Applies to every kind
of change. `82_Automation/check_propagation.pl` reads the subclass table below; a Stop hook enforces it.*

## The rule

1. **Decisions are recorded at the source** (`DECISIONS.md` of the dossier) the moment they are taken.
2. **At the end of the session** every artifact downstream of a changed source is brought up to date **by
   its owner's role**: content rewritten, or — when the change doesn't affect it — its header line
   `reviewed: YYYY-MM-DD ARC-#### — no change` refreshed. Either way the artifact is newer than its sources.
3. **A handoff is executed in the same session** (the main session switches to the destination role) and
   marked `status: done`. An open handoff blocks the end of the session.
4. `55/_wip/` is engineering scratch only — never the home of decisions or texts.
5. The ticket log records which artifacts were updated; then commit + push.

## Change type: system (Woven Spell Slots, Threads, deck, Awakening, keywords…)
Artifacts: `21.05_Class_Features/<System>.md` (design), `26.01` (economy), `25.02_features/FEAT_<System>*.yaml`,
`57.04` / `57.05` cards when it changes how Lua or Osiris is used, `32.01` texts, `05.01` or `05.06`, and each
subclass `DESIGN.md` that uses the system (bump `reviewed` when unaffected).

## Change type: single card / passive / status
Artifacts: its sheet in `23.02`, its YAML in `25`, its text in `32.01`, its test case in `61.02`, the owning
dossier's `DESIGN.md` and `21.03` row, and `05.03` / `05.04` (regenerated by `gen_catalog.pl` after sync).

## Change type: item / equipment
Artifacts: `24_Items_and_Equipment/<Item>.md`, its YAML in `25`, `32.01` text, `42.04` brief, `05` when in game.

## Change type: implementation in the game
After any write in Data: `sync_data` → `gen_catalog.pl` → `05` files (Context Keeper) → test case result
(QA) → spec status (Engineering) → ticket log (Producer).
